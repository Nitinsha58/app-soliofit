# VS-29.8 — Pickup Window + Working-Hours Settings UI (frontend)

**Program:** [VS-29 overview](./00-overview.md) · **Layer:** Frontend · **Status:** Pending
**Depends on:** 29.6 (working-hours data) + 29.7 (template copy with the pickup-window seam).

> **Frontend Design Gate:** read `07-ux-guidelines.md §0` and run §0.10 before editing this UI.

Let the owner set boutique working hours and feed a real `{pickup_window}` into the Ready message.

## Scope (in)

1. **Types** — add `opening_time?` / `closing_time?` to `AuthUser` (`me` payload, 29.6) and to
   `OrderSettings` (`lib/api/auth.ts`).
2. **Settings UI** — two working-hours time inputs (open / close) on the Settings page, in the
   Order Settings section, wired to `updateOrderSettings`. Read-first where it fits the page;
   labelled, validated (open before close mirrors the server).
3. **Pickup-window derivation** — `useWhatsAppSend` reads the auth-store hours and derives the
   window string (e.g. **"between 11 AM and 7 PM"** from `opening_time`/`closing_time`), passing it
   to `buildMessage` / `whatsappUrl`. When hours are unset, the 29.7 fallback
   ("during our working hours") stands.

## Scope (out)

- Backend (done in 29.6). Template copy (done in 29.7).
- Per-day / multi-shift hours, holidays — single open/close pair for now.

## Files

- Modified: `frontend/src/lib/api/auth.ts` (`AuthUser` + `OrderSettings` hours),
  `frontend/src/app/(app)/settings/page.tsx` (hours inputs),
  `frontend/src/lib/useWhatsAppSend.ts` (derive + pass pickup window).

## Review (how to verify)

- `npm run type-check` clean.
- Set working hours in Settings → persist on reload (order-settings).
- A **Ready** order's WhatsApp message shows the derived window (e.g. "between 11 AM and 7 PM");
  with hours unset it reads "during our working hours".

## Done when

Working hours are editable in Settings and the Ready message's `{pickup_window}` reflects them,
with a clean fallback when unset.
