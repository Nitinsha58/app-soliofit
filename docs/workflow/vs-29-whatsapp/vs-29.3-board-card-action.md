# VS-29.3 — WhatsApp Send-Status Footer on Dashboard Cards

**Program:** [VS-29 overview](./00-overview.md) · **Layer:** Backend + Frontend · **Status:** Done (in review)
**ADR:** [ADR-0010](../../adr/ADR-0010-whatsapp-click-to-chat-messaging.md) — scoped extension of the detail-only tracking (no new ADR)
**Depends on:** VS-29.1 (`OrderMessageLog` + `messages_sent`), VS-29.2 (`WhatsAppAction`, templates module).

> **Frontend Design Gate:** read `07-ux-guidelines.md §0` and run §0.10 before editing this UI.

Bring the WhatsApp send-status action onto every dashboard order card, with the same
three-state functioning as the Order Detail button, in a card-appropriate style.

## Scope (in)

1. **Backend — `messages_sent` on the board action only.** `OrderViewSet.get_queryset()`
   adds `'board'` to the actions that `prefetch_related('message_logs')`; the `board` action
   serializes `results` with `OrderDetailSerializer` (which carries `messages_sent`). The page is
   ≤50 rows, so the prefetch is **+1 query per page, not N+1** (asserted by a query-flatness test
   across growing row counts). The generic `GET /api/orders/` list stays on `OrderSerializer`,
   **unchanged** — this is a bounded, board-scoped extension of ADR-0010's detail-only tracking,
   not a new architectural decision.
2. **Shared `useWhatsAppSend` hook** (`lib/useWhatsAppSend.ts`) — extracts the open-draft →
   optimistic (status-keyed) flip → POST → revert-on-fail logic so the detail action and the card
   footer can't drift. `WhatsAppAction` (VS-29.2) is refactored onto it with identical behavior.
3. **`CardWhatsAppFooter`** (`components/dashboard/CardWhatsAppFooter.tsx`) — a compact strip
   merged to the card's bottom edge with a WhatsApp-green hint. Three states (Send / Sent · time +
   Resend / error-retry). **Desktop (`lg`):** hidden until card hover, then shown as an **absolute
   overlay** (no layout shift — siblings don't move; the hovered card lifts via `lg:hover:z-20`).
   **Touch:** always visible, in-flow. **Hidden entirely when the customer has no phone.** Stops
   pointer/click propagation so a tap never starts a drag or opens the drawer.
4. **In-place board cache patch** — on send, the footer updates the `['orders-board', status]`
   recent + older React Query caches, replacing **only the matching order's** `messages_sent` and
   preserving `next_cursor` / `counts` / `value` and every other order exactly.
5. **`BoardColumn`** bottom padding bumped (`pb-3` → `pb-14`) so the last card's hover overlay
   isn't clipped by the column's scroll container.

## Scope (out)

- No change to the generic list/schedule/customer-profile order payloads.
- No new template content (reuses the VS-29.2 templates module).
- No board/card button on the payments board or `ScheduleCard` (dashboard `OrderCard` only).
