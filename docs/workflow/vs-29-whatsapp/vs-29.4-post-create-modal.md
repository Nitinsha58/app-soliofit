# VS-29.4 — Post-Create "Send Booked Message" Modal

**Program:** [VS-29 overview](./00-overview.md) · **Layer:** Frontend · **Status:** Done (in review)
**ADR:** [ADR-0010](../../adr/ADR-0010-whatsapp-click-to-chat-messaging.md)
**Depends on:** VS-29.2 (`useWhatsAppSend`, templates), VS-29.1 (`messages_sent`).

> **Frontend Design Gate:** read `07-ux-guidelines.md §0` and run §0.10 before editing this UI.

Right after an order is created, prompt the owner to send the customer the Booked WhatsApp
confirmation in one tap, then land them on the new order's detail.

## Scope (in)

1. **`OrderCreatedModal`** (`components/orders/OrderCreatedModal.tsx`) — a white success modal
   (centered desktop / bottom sheet mobile, reusing the `AddOrderFlow` shell styling). Green check
   + "Order #XXXX created" + customer name. **One dominant quick action:** green
   **"Send booked message"** (reuses `useWhatsAppSend`; the order is always `Booked` at creation).
   Quiet secondary **"Go to order"**.
2. **"Order details" = the Order Detail drawer.** There is no `/orders/[id]` route; the detail
   surface is the drawer (`openOrderDetail(id)`). **Every exit lands on the new order** — send
   success auto-redirects, and "Go to order" / X / backdrop / Escape all open the drawer too.
3. **Auto-redirect on a recorded send.** `useWhatsAppSend.send()` now returns `Promise<boolean>`
   (true when recorded) so the modal redirects only after the send is logged; the drawer then shows
   "Booked sent" from fresh detail. Existing callers ignore the new return value.
4. **Failure guardrail.** If the POST fails after the draft opened, the modal **stays open** with a
   recoverable error and "Go to order" still works — the user is never stuck.
5. **No-phone orders** hide the WhatsApp button and show only "Go to order".
6. **`AppShell` wiring.** `AddOrderFlow.onCreated(order)` captures the order into `createdOrder`
   state, closes the wizard, and triggers the board refresh (board updates underneath the modal);
   the modal's exit opens the detail drawer.

## Scope (out)

- No backend change (reuses `POST /orders/{id}/messages/`).
- No new route/page; no change to the Add Order wizard steps.
- Only the Booked status is offered here (post-create state); other statuses are sent from the
  drawer (VS-29.2) or board card (VS-29.3).

## Files
