# VS-28.3 — Money Tab (attention-first presentation pass)

**Program:** [VS-28 overview](./00-overview.md) · **Layer:** Frontend · **Status:** Implemented — in review

> **Frontend Design Gate:** read `07-ux-guidelines.md §0` and run §0.10 before editing this UI.

VS-27.5 already delivered the complete, atomic plan editor. 28.3 is a **presentation pass** so the
Money tab reads as a command surface like Work: lead with what's owed, group the plan in one card,
keep the editor one tap away. **No billing logic, math, endpoints, or paid-row locking changed.**

## Scope (in)

- New `MoneyTab.tsx` — one **"Payment Plan"** card framing the VS-27.5 `PaymentSchedule` (parallels
  WorkTab's Work Instructions card).
- `PaymentSchedule` **view mode only**:
  - Lead with **Outstanding as payment-state language** — `₹X outstanding` (amber), `₹X overdue`
    (red, when an unpaid installment is Delayed), or `Paid in full` (green). Bill + Paid become
    secondary context; progress bar + count retained.
  - **"Edit bill & plan" demoted** to a bordered text-gold secondary button (editing the plan is
    admin per §0.7) — secondary, not hidden; bill/date/split changes stay common and reachable.
- "View plan ›" already lands on the Money tab (wired in 28.1).

## Scope (out)

- No billing/backend changes — strict invariant, edit-mode math, mark-paid, and endpoints are
  fixed by VS-27 and untouched.
- **Edit mode untouched** — Save plan stays the dominant action once editing; dirty/cancel/save
  behavior unchanged.
- Overview installments preview **deferred** (avoids a second Overview fetch; Overview stays lean).

## §0.10 pre-build checklist — all "yes"

- Goal in 5s? ✅ outstanding (with state word) is the dominant figure.
- One dominant action? ✅ per-row mark-paid is the money action; edit demoted to secondary.
- Rare actions hidden? ✅ plan editing is secondary; row delete lives inside edit mode.
- Related grouped? ✅ one Payment Plan card.
- Readable without editing? ✅ view mode is read-only; inputs only after "Edit".
- Colors only for meaning? ✅ amber owed / red overdue / green settled.
- Status without calculating? ✅ "outstanding / overdue / Paid in full" pre-computed.
- Destructive separated? ✅ no destructive action in view mode.

## Mobile density pass (2026-06-14, presentational)

- Drawer content padding made responsive: `px-5` → `px-4 lg:px-5` (identity strip, Overview/Work/
  Money wrappers, More Details' OrderInfoSection); Work/Money cards `p-4` → `p-3 lg:p-4`. Desktop
  right-panel unchanged; recovers ~16px/side on mobile.
- **Money edit row split into two rows** (edit mode only): Row 1 = amount (`flex-1`) + a visible
  **32px bordered delete button**; Row 2 = date controls (`QuickDateInput`); note full-width below.
  No change to balance math, dirty/save, mark-paid, paid-locked rows, or the invariant.
