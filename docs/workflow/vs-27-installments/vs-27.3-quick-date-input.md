# VS-27.3 — QuickDateInput Component

**Program:** [VS-27 overview](./00-overview.md)
**Layer:** Frontend (shared component) · **Depends on:** — · **Status:** Pending

A shared, fast date entry control for installment due dates. Native `<input type="date">`
is slow on mobile for quick scheduling; this component optimizes for day + month entry with
the year tucked away.

> **Frontend Design Gate:** read `07-ux-guidelines.md § 0 — Design Standards` in the
> product vault **before** building this, and run the § 0 pre-build checklist. The control
> must follow the attention-first, read-only-by-default, color-=-status rules.

---

## Goal

Make picking an installment due date a one- or two-tap action: day + month with the month
already on the right value, year hidden unless the user needs to change it.

## Behavior

- **Default value precedence** (the "base date" the field initializes from):
  1. the row's **existing due date**, if editing an existing row;
  2. else the **order's delivery date**, if available;
  3. else **today**.
  Day/month quick-edits then adjust *from* that base date — so there is never a "wrong date
  near a month boundary" surprise (we do **not** default month to "current month").
- **Inputs:** day + month, quick to set. **Year is hidden by default**, but it defaults to
  the **base date's year** — *not* always the current year. (If the base date is the
  delivery date next January, the hidden year is next year, so the emitted ISO is correct.)
  The year is revealed only when the user chooses to change it.
- **Output:** an ISO `YYYY-MM-DD` string (the format the API expects).
- Controlled component: `value` / `onChange`, with `deliveryDate?` for default derivation.

## Scope (out)

- No backend changes. No business validation here (balance checks live in the editors).
- Not a general-purpose date range picker — single due date only.

## Files

- `frontend/src/components/common/QuickDateInput.tsx` *(new)*

## Proposed interface

```ts
interface QuickDateInputProps {
  value: string                 // 'YYYY-MM-DD' (may be empty)
  onChange: (iso: string) => void
  deliveryDate?: string         // used to derive the default when value is empty
  // year hidden by default; component exposes an affordance to reveal/change it
}
```

## Review (how to verify)

- Type-check via Docker: `docker compose -f docker-compose.dev.yml exec frontend npm run type-check`
  (frontend has no test framework / usable lint — verify by type-check + browser).
- Manual: confirm default precedence (existing → delivery → today), month-boundary safety,
  and that year stays hidden but is editable on demand. Output is always valid ISO.
- Hand off to Nitin + automation testing tool for the browser pass.

## Done when

default, and passes the § 0 checklist. (It is wired into editors in 27.4 / 27.5.)
