# VS-27.5 — Drawer "Edit Bill & Plan"

**Program:** [VS-27 overview](./00-overview.md) · **ADR:** [ADR-0009](../../adr/ADR-0009-strict-installment-plan.md)
**Layer:** Frontend (Order Detail drawer) · **Depends on:** 27.1, 27.3 · **Status:** Pending

Replace the order drawer's one-at-a-time, immediately-POSTed installment editing with a
**whole-plan editor** in which the bill and the unpaid schedule are edited together and
saved atomically — never disturbing paid installments.

> **Frontend Design Gate:** read `07-ux-guidelines.md § 0` before editing this UI and run
> the § 0 pre-build checklist.

---

## Goal

Make the schedule editor a calm **"Review & save payment plan"** surface where the bill and
unpaid installments form one balanced plan, committed in a single atomic call.

## Behavior

1. **Two row classes, clearly separated**
   - **Paid rows** — locked: shown, never editable/removable, excluded from staging.
   - **Unpaid rows** — one editable draft set: add / edit / remove freely.
2. **Bill is editable in this mode** (the "Edit bill & plan" affordance). Changing the bill
   re-targets the balance the unpaid rows must hit.
3. **Save gating** — the Save action is enabled only when:
   - `total_amount ≥ Σ(paid)` (can't drop the bill below what's already paid), **and**
   - `Σ(paid) + Σ(staged unpaid) == total_amount` (the plan balances).
   Otherwise show a calm status ("Remaining ₹X" / "Over by ₹X" / "Bill below paid").
4. **Sticky save bar** appears **only when there are unsaved changes** — this is the
   deliberate, justified exception to autosave (money schedules need atomicity). When clean,
   the editor is read-only-by-default with no save bar.
5. **One atomic commit** → `PUT /api/orders/{id}/billing/` with
   `{ total_amount, installments: [unpaid set] }`. On success, re-sync from the response;
   paid rows are guaranteed untouched.
6. Use **`QuickDateInput`** (27.3) for due dates.

## Scope (out)

- No backend changes (consumes 27.1's `PUT …/billing/`).
- `mark-paid` stays the existing single action (paid is a domain event, not a plan edit).

## Files

- `frontend/src/components/orders/OrderDetailDrawer/PaymentSchedule.tsx` — rebuilt editor
- `frontend/src/components/orders/OrderDetailDrawer/InstallmentSection.tsx` — wiring (if the
  bill field moves into the editor's scope)
- `frontend/src/lib/api/installments.ts` — `replaceSchedule(orderId, { total_amount, installments })` (PUT)
- (possibly) the order drawer's bill field becomes read-only outside "Edit bill & plan"

## Review (how to verify)

- Type-check via Docker: `docker compose -f docker-compose.dev.yml exec frontend npm run type-check`.
- Manual scenarios:
  - Open an order with paid + unpaid rows → paid rows locked; editing unpaid shows the
    sticky save bar; save only enables when balanced.
  - Edit one unpaid amount and rebalance another → single Save commits both atomically; paid
    rows unchanged.
  - Increase/decrease the bill → unpaid plan must rebalance before Save enables; cannot set
    bill below paid.
  - No unsaved changes → no save bar; read-only.
- Confirm the request is a single `PUT …/billing/` and paid rows are preserved server-side.
- Hand off to Nitin + automation testing tool.

## Done when

The drawer edits bill + unpaid plan as one balanced, atomic unit; paid rows are never
disturbed; the sticky save bar appears only on dirty state; quick date entry is in use.
